# 教师端开发报告

## 一、模块概述

教师端是教学事务管理系统面向任课教师的业务模块，覆盖教师日常教学管理中的主要工作，包括授课课表查看、教学班详情查看、学生名单查看、成绩录入与提交、已提交成绩修改申请、调课申请、考试安排查看与修改申请、学生退课审核、个人信息维护、当前学期展示和首页教学待办提醒。

系统整体采用 Vue 前端、Spring Boot 后端和 MySQL 数据库。教师端页面集中在 `frontend/src/views/teacher`，前端接口封装在 `frontend/src/api/teacher.js`，后端控制器、服务和数据访问逻辑集中在 `com.school.teacher` 包。成绩审核、调课审核、考试修改审核和成绩提交时间设置属于教师业务闭环中的管理员协作部分，由管理员端对应页面和接口完成。教师端导航中“调课申请”作为一级菜单单独展示，“审核处理”保留退课审核和补考确认。

## 二、实体设计

教师端实体设计围绕“教师、教学班、学生、成绩、申请、学期”展开。各实体之间通过教学班形成业务关联。

### 1. 教师实体

`teacher` 表表示教师基础资料，包括工号、姓名、性别、出生日期、职称、学历、所属院系、状态、手机号和邮箱。

教师端以教师工号作为身份边界。教师登录后只能访问本人相关的授课、成绩、调课和退课数据。

### 2. 教学班实体

`teaching_class` 表表示具体教学安排，是教师端最核心的业务实体之一。

主要信息包括：
- 教学班编号。
- 所属学期。
- 课程编号。
- 任课教师。
- 教室。
- 开课日期。
- 星期、节次和周次。
- 容量上限和已选人数。
- 教学班状态。

教师端授课课表、教学班详情、学生名单、成绩录入、调课申请和考试安排都围绕教学班展开。

### 3. 学生与选课实体

`student` 表保存学生基础信息，`course_selection` 表记录学生和教学班之间的选课关系。

教师端查看学生名单时，只展示 `selection_status = '已选'` 的学生。退课后的记录保留为 `已退`，用于保留选课历史并支持后续重新选课。

### 4. 成绩实体

`score` 表保存学生在教学班中的成绩信息，包括平时成绩、考试成绩、总评成绩、绩点、是否提交和录入时间。

成绩实体的核心状态是 `is_submitted`：
- `0` 表示暂存，教师仍可修改。
- `1` 表示已提交，教师端默认只读。

总评成绩和绩点由数据库触发器根据平时成绩和考试成绩计算。

### 5. 成绩修改申请实体

`score_change_request` 表表示教师对已提交成绩的修改申请。

该实体记录申请对应的成绩、教师、学生、教学班、原成绩快照、申请原因、审核状态和管理员审核信息。通过该实体，系统将“已提交成绩不可直接修改”和“确有需要时可申请退回修改”两个要求统一起来。

### 6. 调课申请实体

`schedule_adjust_request` 表表示教师调课申请。

该实体记录原星期、原节次、原周次、原教室，以及申请后的星期、节次、周次和教室，同时保存申请原因、审核状态和管理员审核信息。

当前调课规则限制为：周次保持不变，节次跨度保持一致，目标教室需要避开同时间段占用，同一教师在同一星期同一节次不能安排两门课程。教师可撤销本人状态为“待审核”的调课申请。

### 7. 考试安排与考试修改申请实体

`exam_arrangement` 表表示考试安排，记录教学班、考试日期、考试起止时间、考试教室和考试状态。

`exam_change_request` 表表示教师发起的考试安排修改申请，记录原考试日期、原时间、原教室，以及申请后的日期、时间、教室、申请原因、审核状态和管理员审核信息。

考试修改规则包括：同一考试不能重复提交待审核申请；目标教室在申请后日期和时间段不能被其它考试占用；同一教师同一时段不能有两门本人教授课程考试。教师可撤销本人状态为“待审核”的考试修改申请。

### 8. 学期实体

`semester` 表表示学期设置。教师端主要使用其中的选课时间和成绩提交时间信息。

成绩提交时间由 `score_submit_start` 和 `score_submit_end` 控制。教师可以暂存成绩，但正式提交成绩必须处于成绩提交时间范围内。教师端主布局会展示当前学期名称和起止日期；教师授课课表页支持按不同学期切换查看，并展示对应学期的选课状态。

## 三、数据库设计

教师端数据库设计重点在于保证教学数据的归属关系、状态流转和业务约束。

### 1. 教师与教学班关系

`teaching_class.teacher_id` 指向任课教师。教师端所有关键查询都基于该字段限制数据范围。

这种设计使教师端无需额外维护权限映射表，只要教学班归属正确，后端即可通过教学班归属校验控制访问边界。

### 2. 教学班与学生关系

`course_selection` 记录学生是否选择某个教学班，并通过 `selection_status` 表示选课状态。

同一学生和同一教学班之间存在唯一约束，避免重复选课。退课时不删除选课记录，而是将状态更新为 `已退`。当学生重新加入同一教学班时，系统恢复原记录为 `已选`。

### 3. 成绩数据设计

`score` 表以学生和教学班为核心维度保存成绩。教师录入成绩时，系统根据学生是否已选该教学班确定成绩录入范围。

学生退课后，系统清理该学生在对应教学班中的成绩记录，避免重新加入课程后继续保留旧成绩。

### 4. 成绩提交时间设计

`semester.score_submit_start` 和 `semester.score_submit_end` 表示成绩提交开放时间。

成绩提交校验放在后端服务层，而不是只依赖前端按钮状态。这样即使前端状态过期或被绕过，后端仍能保证成绩提交规则。

首页成绩录入提醒也使用该时间窗口：不在开放时间内时，未录入和未提交成绩显示为 `--`；处于开放时间内且仍有未录入或未提交成绩时才统计并提醒教师处理。若成绩已全部提交，即使仍处于成绩提交时间范围内，首页也不再弹窗提醒。

### 5. 调课占用设计

教室占用不单独建表，而是直接由 `teaching_class` 中的学期、星期、节次和教室字段表示。

查询空教室和审核调课申请时，系统会检查同学期、同星期、同教室下是否存在节次区间重叠的教学班。教师提交调课申请和管理员审核通过时，还会检查同一教师在目标星期和节次是否已有其它教学班课程。该方式避免了排课数据和占用数据不一致的问题。

### 6. 考试占用设计

考试占用不单独建表，而是直接由 `exam_arrangement` 中的考试日期、起止时间和教室字段表示。

教师端考试修改申请的可选教室接口会按申请后的日期和时间段动态排除已被其它考试占用的教室，并在教室选项中显示容量。如果申请时间与当前教师其它考试冲突，后端直接返回“申请时间冲突”，前端清空教室选项并提示。

### 7. 申请审核数据设计

成绩修改申请、调课申请和考试修改申请都采用独立申请表保存。

申请表统一包含：
- 申请对象。
- 申请人。
- 原始业务数据。
- 申请后的目标数据或申请原因。
- 审核状态。
- 审核意见。
- 审核人和审核时间。

这种设计可以保留完整审核轨迹，也便于教师查看申请进度。调课申请和考试修改申请支持教师撤销待审核申请，撤销后状态更新为“已撤销”。

## 四、接口对接设计

教师端接口统一使用 `/api/teacher` 路径。前端通过 `teacher.js` 封装请求，页面组件只调用语义化方法，减少接口路径散落在页面中的情况。

### 1. 教师个人信息接口

- `GET /api/teacher/profile`
- `PUT /api/teacher/profile`

该组接口用于展示和维护教师个人信息。教师可以修改手机号和邮箱，身份、院系、职称等基础信息只读。

### 2. 授课与学生名单接口

- `GET /api/teacher/teaching-classes`
- `GET /api/teacher/teaching-classes/{teachingClassId}`
- `GET /api/teacher/teaching-classes/{teachingClassId}/students`

该组接口支撑教师授课课表、教学班详情和学生名单。后端会校验教学班是否属于当前教师。

`GET /api/teacher/teaching-classes` 默认只返回当前学期教学班；教师授课课表页通过 `includeAllSemesters=true` 获取全部学期教学班，用于按学期切换课表。授课列表和教学班详情返回课程的平时成绩占比、考试成绩占比，用于展示“平时:考试”比例。

### 3. 成绩录入接口

- `GET /api/teacher/scores`
- `POST /api/teacher/scores`
- `POST /api/teacher/scores/batch`
- `GET /api/teacher/scores/submit-window/{teachingClassId}`

该组接口支撑成绩列表查询、单条成绩保存、批量成绩保存和成绩提交时间窗口查询。成绩录入页常驻显示成绩录入截止时间，按当前筛选教学班展示对应截止时间；未筛选时只在未完成成绩录入的教学班中选择截止时间，优先展示未来最近截止时间。离线成绩导入复用批量保存接口，导入后统一按未提交状态暂存。

成绩保存接口通过 `isSubmitted` 区分暂存和提交。提交时校验成绩提交时间，暂存时允许教师随时保存草稿。

### 4. 成绩修改申请接口

- `GET /api/teacher/score-change-requests`
- `POST /api/teacher/score-change-requests`

该组接口用于教师查看本人提交的成绩修改申请，以及对已提交成绩发起修改申请。

管理员端对应接口负责审核申请。审核通过后，成绩状态回到未提交，教师可重新修改。

### 5. 调课申请接口

- `GET /api/teacher/available-classroom-options`
- `GET /api/teacher/schedule-adjust-requests`
- `POST /api/teacher/schedule-adjust-requests`
- `PUT /api/teacher/schedule-adjust-requests/{adjustRequestId}/cancel`

该组接口用于查询空教室、查看调课申请记录、提交调课申请和撤销待审核调课申请。空教室接口基于教学班时间和教室占用情况动态返回结果。

管理员端对应接口负责审核调课申请。审核通过后，教学班排课信息随之更新。

### 6. 考试安排与考试修改申请接口

- `GET /api/teacher/exams`
- `GET /api/teacher/exam-change-requests`
- `GET /api/teacher/exam-available-classroom-options`
- `POST /api/teacher/exam-change-requests`
- `PUT /api/teacher/exam-change-requests/{examChangeRequestId}/cancel`

该组接口用于教师查看当前学期本人课程考试安排、查询本人考试修改申请、按申请后日期和时间动态查询可用考试教室、提交考试修改申请和撤销待审核考试修改申请。

考试可用教室接口会返回包含容量的教室选项，并排除同日期同时间段已被其它考试占用的教室。若申请时间与教师本人其它考试冲突，接口返回“申请时间冲突”。

管理员端对应接口负责审核考试修改申请。审核通过后，考试安排随之更新，并会再次复核教室占用和同教师考试时间冲突。

### 7. 当前学期接口

- `GET /api/teacher/current-semester`

该接口用于教师端主布局展示当前学期名称和学期起止日期。

### 8. 退课审核接口

- `GET /api/teacher/course-drop-requests`
- `PUT /api/teacher/course-drop-requests/{dropRequestId}/review`

该组接口用于教师查看和审核学生退课申请。教师审核结果与管理员审核结果共同决定退课申请最终状态。

### 9. 首页待办接口

- `GET /api/teacher/todos`

该接口返回教师首页待办数量，包括退课待审核、成绩待处理、调课待审核等。

成绩相关待办结合成绩提交时间窗口统计，避免在成绩提交未开放时显示不可处理的任务数量。首页会基于退课、补考、成绩和调课待办总数显示状态标签：存在待办时显示待处理数量，不存在待办时显示“暂无待办”。

## 五、前端设计

教师端前端以“清晰、直接、便于重复使用”为设计原则。整体界面延续系统后台管理风格，使用表格、课表网格、抽屉、表单、待办卡片等组件组织教学事务。

教师端主菜单将高频业务直接平铺展示，其中“调课申请”从“审核处理”中移出，作为独立入口；审核处理下只保留需要教师审核或确认的退课审核和补考确认。

### 1. 授课管理页面

授课管理页以周课表网格呈现教师课程安排。横向为周一到周日，纵向为上午、下午和晚上。课程卡片展示课程名称、节次、教学班编号、周次、教室和选课人数。

页面支持选择不同学期查看课表，默认优先显示当前学期。课表上方展示所选学期名称、学期起止日期、是否当前学期和选课状态，状态样式参考管理员端学期管理。

页面提供教学班详情抽屉，教师可以从课表直接进入课程详情和学生名单。

课表 PDF 导出使用浏览器打印能力实现。系统生成一个独立打印页，保持接近页面课表的网格和卡片风格，再由浏览器保存为 PDF。导出范围与当前选择的学期一致。

### 2. 成绩录入页面

成绩录入页以表格为主。教师可以按教学班筛选学生成绩，筛选项显示教学班编号、课程名称、学期、星期、节次和周次，便于导入成绩前确认教学班。教师可以查看课程“平时:考试”比例，并录入平时成绩和考试成绩。页面顶部常驻显示成绩录入截止时间，帮助教师在录入过程中持续确认提交期限；已全部提交成绩的教学班不再显示截止时间。

页面支持：
- 单条暂存。
- 单条提交。
- 批量暂存。
- 批量提交。
- 已提交成绩只读。
- 成绩统计和绩点分布。
- 成绩 CSV/XLSX 导出和离线填写后导入。
- 已提交成绩修改申请。

统计卡片显示当前筛选范围内的学生人数、平均分、最高分、最低分和及格率，方便教师在提交前检查整体成绩情况。绩点分布按当前筛选范围内已生成绩点的成绩记录统计，展示绩点、评价符号、人数和占比；评价符号复用学生端成绩视图的 11 档规则。

成绩导入面向当前筛选范围内的成绩列表。教师可先导出 CSV 或 XLSX，离线填写平时成绩和考试成绩后再导入。导入时前端按表头识别学号、姓名、教学班编号、平时成绩和考试成绩，不依赖行顺序；只导入平时成绩和考试成绩，忽略总评成绩、绩点和提交状态等其它列。已提交成绩不会被导入覆盖；如果没有教学班编号且同一学生在当前范围内匹配多条未提交成绩，则跳过该行，避免误写。XLSX 读写由前端按需加载 `xlsx` 依赖完成，不新增后端上传接口。

### 3. 调课申请页面

调课申请页以表单和申请记录列表组成。

教师选择教学班后，页面自动带出原星期、节次和周次。周次不可编辑，节次选项根据原节次跨度限制。选择星期后，节次下拉会隐藏该教师同一星期其它教学班已占用或重叠的节次。目标教室根据所选时间动态加载空教室。

申请记录列表展示申请状态、申请内容和审核意见，便于教师追踪处理进度。待审核申请可由教师撤销。

### 4. 考试安排页面

考试安排页面展示当前学期本人课程的考试日期、考试时间、考试地点和考试状态。教师可对考试时间或地点提交修改申请。

申请修改考试安排时，教师选择开始时间后，结束时间默认填充为开始时间后 2 小时。考试教室下拉根据申请后的日期和时间动态加载可用教室，并显示教室容量；若申请时间与本人其它考试冲突，页面会提示“申请时间冲突”并清空可选教室。

考试修改申请列表展示原安排、申请后安排、申请原因、审核状态和审核备注。待审核申请可由教师撤销。

### 5. 退课审核页面

退课审核页面展示学生退课申请及其当前审核状态。教师可查看申请原因，并选择通过或驳回。

### 6. 个人信息页面

个人信息页面展示教师身份和联系信息。身份类字段只读，手机号和邮箱可维护。

### 7. 首页待办设计

首页对教师角色展示教学待办卡片。

退课待审核和调课待审核始终显示实际数量。成绩相关待办只在成绩提交开放时间内显示数量，不在开放时间内显示 `--`，并通过鼠标悬停提示“当前不在相关事务的开放时间内”。

教学待办标题区显示待办状态标签：存在待办时显示黄色待处理数量，不存在待办时显示绿色“暂无待办”。处于成绩提交时间范围内且仍有未录入或未提交成绩时，教师登录进入首页会弹窗提醒成绩录入状态；成绩已全部提交时不再弹窗。

### 8. 当前学期展示

教师端主布局在顶部展示当前学期名称和学期起止日期，帮助教师明确当前系统业务上下文。

## 六、功能介绍

### 1. 授课课表

教师可以按学期查看本人课程安排，了解每门课程的上课时间、周次、教室和选课人数。课表显示所选学期的起止日期、是否当前学期和选课状态，并支持按当前学期筛选结果导出 PDF，便于打印或归档。

### 2. 教学班详情

教师可以查看教学班对应课程的详细信息，包括课程编号、课程类型、学分、考核方式、平时与考试成绩占比、开课院系、容量和状态。

### 3. 学生名单

教师可以查看教学班已选学生名单，并了解每个学生的行政班、专业、院系、联系方式和成绩状态。

### 4. 成绩录入

教师可以录入学生平时成绩和考试成绩，系统计算总评成绩和绩点。成绩支持暂存和提交两种状态，提交后默认只读。教师可按当前筛选范围查看人数、平均分、最高分、最低分、及格率和绩点分布。

### 5. 成绩修改申请

已提交成绩需要修改时，教师提交修改申请。管理员审核通过后，成绩退回为可修改状态，教师再重新录入并提交。

### 6. 调课申请

教师可以提交调课申请。系统限制周次不变、节次跨度一致，并自动筛选目标时间段可用教室；同一教师同一时间已有课程时不能提交申请。管理员审核通过后，教学班排课信息更新。待审核申请可撤销。

### 7. 考试安排修改申请

教师可以查看本人课程考试安排，并提交考试时间或教室修改申请。系统会按申请后时间筛选可用考试教室，显示教室容量，并拦截教室占用和同教师考试时间冲突。待审核申请可撤销。

### 8. 退课审核

教师参与学生退课申请审核。退课通过后，学生选课状态变为已退，对应成绩记录清理。

### 9. 个人信息维护

教师可以维护本人手机号和邮箱，保证教学事务联系信息准确。

### 10. 教学待办提醒

教师首页集中展示待处理事务，并通过黄色或绿色状态标签快速区分是否存在待办。成绩录入提醒与成绩提交时间窗口联动，避免在不可提交时间显示无效待办；成绩已全部提交时，即使仍处于提交窗口内，也不会继续弹窗提醒。

## 七、实现简介

### 1. 后端实现

后端采用 Controller、Service、Mapper 分层实现。

`TeacherController` 负责暴露教师端接口；`TeacherService` 负责业务规则处理；`TeacherMapper` 负责 SQL 查询和更新。

关键实现包括：
- 教学班归属校验，保证教师只能操作本人教学班。
- 成绩提交时间校验，保证成绩提交符合学期设置。
- 成绩修改申请状态校验，避免重复申请。
- 调课申请规则校验，保证周次不变、节次跨度一致，并拦截同教师授课时间冲突。
- 空教室查询和审核时的节次重叠判断。
- 考试修改申请校验，拦截同教室考试时间冲突和同教师考试时间冲突。
- 调课申请和考试修改申请撤销校验，确保只能撤销本人待审核申请。
- 退课通过后的选课状态更新和成绩清理。

### 2. 前端实现

前端使用 Vue 3 组合式 API 和 Element Plus 组件。

页面层通过 `teacher.js` 调用后端接口，组件内部使用响应式数据和计算属性完成筛选、统计、按钮禁用和状态展示。

课表页面使用 CSS Grid 实现周课表布局，并通过学期筛选展示不同学期课表；成绩页面使用表格、统计卡片和绩点分布面板组织成绩录入；调课页面使用表单联动空教室接口；考试安排页面使用表格、弹窗表单和动态教室选项完成考试修改申请；首页使用待办卡片、状态标签和条件弹窗提示教师当前需要关注的教学事务。

### 3. 管理员协作实现

教师端部分流程需要管理员协作完成闭环，包括成绩提交时间设置、成绩退回、成绩修改审核、调课审核和考试修改审核。

管理员端负责维护系统级设置和审核结果，教师端负责发起申请、查看状态和继续处理审核后的业务。

## 八、总结

教师端模块围绕任课教师的日常教学工作建立了完整业务链路。实体层以教师、教学班、选课、成绩和申请为核心；数据库层通过状态字段和申请表保存业务过程；接口层围绕教师工作流拆分为授课、成绩、调课、退课、个人信息和待办；前端层通过课表、表格、抽屉、表单和待办卡片提供直接可用的操作界面。

整体设计既覆盖教师端已有基础功能，也整合了成绩提交控制、成绩修改申请、调课申请、考试修改申请、多学期课表和教学提醒等配套能力，使教师端能够支撑较完整的教学事务处理流程。
